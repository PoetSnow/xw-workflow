# 组织 / RBAC / 审批 分层方案（评审稿）

原则：**审批流不能拿 RBAC 当组织架构。**  
RBAC 管「能不能做这个操作」。组织/任职管「他在企业里是什么身份」。审批再按单据部门和业务规则解析「这一单现在该谁批」。

本方案只改边界和找人规则。流程、节点、条件、实例、任务、历史可以留。

---

## 1. 现状问题

| 层 | 现在 | 问题 |
|---|---|---|
| 组织 | `sys_user.deptid` 一人一个部门；`sys_organization` 有树 | 表达不了「A 部员工 + B 部经理」 |
| RBAC | `sys_role` + `sys_role_user_relation`（用户×角色，无部门） | `DEPT_MANAGER` / `STRATEGY_OFFICE` 既是菜单角色又是审批身份 |
| 审批 | 解析器 `Role` / `RoleInDept` / `User`，`resolvervalue` 是角色 code | 找的是「谁有这个角色」，不是「单据部门上谁任职这个岗位」 |

一人多部门、本级找不到就往上找、自己批自己，在这套模型里都没有唯一起点。

---

## 2. 三层怎么分

```
组织          用户 · 部门 · 岗位 · 任职
   ↓ 单据冻结 DeptId
审批          流程 · 节点 · 条件 · 按岗位解析 · 实例 / 任务 / 历史
   ↓ 打开功能、点按钮
RBAC          用户 · 角色 · 权限 · 角色权限 · 数据范围
```

| 层 | 只回答 | 不回答 |
|---|---|---|
| 组织 | 他在哪个部门担任什么岗位 | 能不能进采购单页面 |
| RBAC | 能不能建单、提交、看待办、数据看多大 | 这一单的部门经理是谁 |
| 审批 | 这一单当前环节派给哪个任职上的人 | 菜单和接口权限 |

口头可以说「这个角色去批」，落库必须是**岗位**，不能是 `sys_role`。

---

## 3. 第一层：组织

### 3.1 已有

- `sys_user`：人。现有 `deptid` 降级为**主职部门**（冗余，方便列表），不再表示唯一任职。
- `sys_organization`：部门树。`parentid` / `parentids` 继续用于往上找。

### 3.2 新增

**岗位 `sys_position`**

- `code` / `name`：如 `DEPT_MANAGER` 部门经理、`DEPT_SUPERVISOR` 部门主管、`STRATEGY_DIRECTOR` 战略办主任
- `level`：职级，只用于比较高低，不拿来当全局头衔
- 岗位是目录，不绑人、不绑部门

**任职 `sys_user_appointment`**

- `userid` + `deptid` + `positionid`
- `isprimary`：是否主职（每人恰好一份主职）
- `status` / 生效区间：兼岗取消、调岗改任职，不改用户本身

张三 = 两条任职，不是「张三既是员工又是领导」：

- 张三 / 设备科 / 员工 / 主职
- 张三 / 战略办 / 主任 / 兼岗

### 3.3 汇报线

**已定：第一期不要汇报线。** 往上找人只走部门树：本级该岗位无人 → 父部门同岗位。不做人与人的直属上级。

---

## 4. 第二层：RBAC（基本不动）

继续用 `sys_role` / `sys_role_menu_relation` / `sys_role_user_relation` / `datascope`。

角色只做权限包：系统管理员、访问者、采购员、审批办理（能进待办页）。

从 `sys_role` **迁出**这些审批身份，一律改为岗位（已定：财务、总经理也岗位化，不指定人）：

- `DEPT_MANAGER` 部门经理、`DEPT_SUPERVISOR` 部门主管、`GM` 总经理、`FINANCE` 财务、`STRATEGY_DIRECTOR` 战略办主任

一个人可以同时：RBAC = 采购员（能开单），任职 = 设备科员工 + 战略办主任。两套互不替代。

数据范围仍按 RBAC `datascope`。若以后要「看本部门及下级」，范围按组织树算，规则仍挂在角色上，不挂到审批。

---

## 5. 第三层：审批

引擎（图、XOR、实例、任务、历史、当前进度/历史记录 UI）保留。

### 5.1 单据必须带审批部门

每张要送审的单有且仅有一个**审批用部门**，提交时写入业务表并冻结进 `formsnapshot.DeptId`，同时写入 `appr_instance.submitdeptid`。

规则：

1. 提交人只有一份有效任职：自动带该部门，不必选。
2. 多份任职：提交前必选「这一单以哪个部门发起」，不选不能提交。
3. 审批过程中禁止改 `DeptId`；驳回后重新提交可以改。
4. 单上若还有费用部门、收货部门，必须标明哪一个是审批用部门。

采购单：补齐/使用单据 `DeptId`，提交审批前按上面三条校验。

### 5.2 设计器：审批人改为岗位，不再选 RBAC 角色

节点解析只保留：

| 类型 | 含义 | 起点 |
|---|---|---|
| `PositionFromDocDept` | 单据部门上的某岗位；无人则沿父级 | `DeptId` |
| `PositionInFixedDept` | 固定真实部门 + 岗位（战略办 + 主任） | 设计时写死部门 |
| `User` | 指定人 | 例外 |
| `Submitter` | 发起人 | 退回确认类 |

删除（或下线，存量迁移后禁止新建）：`Role`、`RoleInDept`。

往上找的默认规则：从 `DeptId` 开始，本级该岗位有有效任职就全派（或签/会签仍看节点模式）；没有就 `parentid` 再找，找到或到根为止。找不到则提交失败，不静默跳过。

### 5.3 派任务按任职，展示带部门

待办记 `assigneeuserid` + 当时的 `deptid` + `positionid`（任务表补两列，或写入任务快照）。  
界面：「战略办 · 主任 · 张三」，不要只写「张三」。

### 5.4 自己批自己

**已定：允许。** 往上走到自己是父级该岗位时，待办仍派给他，界面标明部门 + 岗位，不跳过、不失败。

### 5.5 在途单与组织变更

**已定：沿用提交时冻住的人。** 提交时走完全路径并解析审批人，写入任务；到达环节只激活已冻住的人，不按当时任职重找。调岗、兼岗取消只影响新单。驳回再提交：按新的任职和用户重选的 `DeptId` 重新走路径。

## 6. 复用怎么做（先梳理，再压缩）

不要先画「全公司一个采购流程」。先摊表：

| 业务 | 发起部门 | 条件 | 第 1 环 | 第 2 环 | 第 3 环 |
|---|---|---|---|---|---|
| 采购 | 某科室 | 金额 ≤ 300 | 本级部门经理 | 结束 | |
| 采购 | 某科室 | 金额 > 300 | 本级部门经理 | 战略办主任 | 结束 |

复用的是路径形状和解析规则，不是一张图打天下：

- 同一形状多部门：一条流程 + 绑定业务类型；部门由单据 `DeptId` 运行时解析  
- 归口：战略办是组织树上的真实部门，节点用 `PositionInFixedDept`（战略办 + 主任岗），不要每个科室画一个战略办节点  
- 只有形状真不一样才拆第二条流程  

落地顺序：组织树和任职 → 真实审批表 → 抽 2～3 条可绑定流程 → 再改设计器和解析器。

---

## 7. 建议改动范围（相对现网）

**要改**

- 新增岗位、任职；用户维护改为「多任职 + 一份主职」
- 送审单据强制 `DeptId`，多部门提交人自选
- 审批解析和设计器从角色改为岗位
- `DEPT_MANAGER` 等从 `sys_role` 迁到 `sys_position`，角色表只留权限包
- 任务/时间线展示带部门 + 岗位

**不改**

- 审批实例状态机、XOR 条件、待办激活时机（到达才 Pending）
- 当前进度 vs 历史记录这套 UI
- RBAC 菜单、按钮、数据范围机制

**任务表**

- 现有 `appr_task.assigneeroleid` → `sys_role` 不再用于找人  
- 改为 `positionid` + `deptid`（或等价快照），`assigneeuserid` 仍是具体人

---

## 8. 落地阶段

1. **梳数据（不改引擎）**  
   部门树、每人任职、哪份主职。把现在 `sys_role` 里的审批身份标出来，准备迁岗。
2. **组织表 + 维护界面**  
   岗位、任职。`sys_user.deptid` 与主职任职对齐。
3. **单据 DeptId**  
   采购单先做：单部门自动带、多部门必选、无部门不能提交。
4. **审批解析切换**  
   新解析器上线；设计器选项替换；已发布流程重绑岗位后发布新版本。旧实例仍按旧解析结果只读。
5. **清理 RBAC**  
   审批用角色从角色表移除或停用，避免再被画进流程图。

---

## 9. 已定结论

| # | 题目 | 结论 |
|---|---|---|
| 1 | 往上走到自己 | 允许，待办仍给他，文案带部门身份 |
| 2 | 汇报线 | 不要 |
| 3 | 战略办 | 真实部门 + 主任岗位，`PositionInFixedDept` |
| 4 | 财务 / 总经理 | 岗位化，不指定人 |
| 5 | 到达下一环 | 沿用提交时冻住的人，不重找 |

可以按第 8 节阶段改，不必一次重做整套审批。需要动手时再说从哪一阶段开始。
